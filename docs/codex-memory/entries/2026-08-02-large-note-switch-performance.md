# 大笔记切换优化

## 问题

网页端每次切换笔记都会重新请求完整正文，切回刚看过的大笔记也不例外。同时 Milkdown 在替换正文前调用 `getMarkdown()`，会先把当前大文档完整序列化，再解析目标文档，放大了主线程卡顿。

## 处理

- 笔记 Store 增加最近使用详情缓存，最多保留 6 篇，并以 32 MiB 字符总量控制常规缓存规模；单篇超大笔记最多独占一个缓存项。
- 切换离开时保存当前最新内存快照，切回时优先复用，避免重复详情请求。
- Store 销毁时释放缓存，历史恢复后用服务端最新详情覆盖缓存。
- Milkdown 使用已有 `contentValue` 判断正文是否变化，不再为比较而调用 `getMarkdown()` 序列化旧文档；父组件回传相同正文时也不重复解析大纲。

## 验证

- Store 单测覆盖 1→2→1 切换仅请求两次详情。
- 编辑器回归测试约束 `setContent` 不调用 `getMarkdown()`。
